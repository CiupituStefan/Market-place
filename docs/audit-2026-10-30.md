# Website audit and remediation — 2026-10-30

Scope: the whole repository (Next.js storefront, nine NestJS services, API gateway, shared
packages, deployment files) and the live deployment (csekeyboards.com on Vercel,
api.csekeyboards.com on a Google Cloud VM), tested only with read-only or own-data requests.

Status labels: **[PASS]** verified working · **[FIXED]** found and corrected (and tested) ·
**[FAIL]** unresolved · **[NEEDS MANUAL ACTION]** needs the owner, credentials or a lawyer ·
**[NOT APPLICABLE]** · **[NOT VERIFIED]** could not be checked.

"Live" means checked against the deployed site; fixes marked _(deploys with the VM update)_ are
in Git but reach the API server only when the owner runs the update in
[Manual actions](#19-manual-actions-for-the-owner).

## 1. Executive summary

The code base was already security-conscious (server-side prices, signed webhooks, idempotency,
strict CSP, rate limits, Argon2id, HttpOnly cookies, parameterised queries, per-service
databases). The serious problems were in **what is deployed** and **what the site claims**:

1. **Critical:** the live storefront ran a Next.js version with two published unauthenticated
   remote-code-execution advisories. **Fixed** (deployed to Vercel).
2. **High:** the live shop accepted orders and marked them **paid without any money** (the
   payment simulator is reachable by anyone), and the webhook signing secret was the public
   default from this repository. With no registered business, orders must not be possible at
   all. **Fixed** in code (preview mode, generated secrets); the storefront part is live, the
   server part deploys with the VM update.
3. **High (legal):** the catalog showed **made-up star ratings and review counts**,
   "Bestseller"/"Limited" badges and **fake "was" prices** — fake reviews and fake reference
   prices under EU consumer law. **Fixed** in code; removed from the live database by the VM
   update.
4. **Legal:** no business identity exists yet, so there can be no compliant seller information.
   The legal pages were rewritten from what the code actually does, with every company detail
   left as a visible placeholder and a "draft, legal review pending" notice. **Needs a lawyer and
   the business details.**
5. **Email:** no email reaches anyone (the VM keeps all mail in Mailpit), the domain has **no MX,
   SPF or DMARC** records. Account confirmation, password reset and the newsletter do not work
   for real users yet. **Needs an email provider and DNS changes.**

**Production readiness:** acceptable as a **non-selling preview** once the VM update is applied.
**Not ready to sell**: that needs a registered business, completed and reviewed legal pages, a
real payment provider (Stripe, live keys), a real email provider, and the items in section 17.

## 17. Remaining unresolved issues

1. No registered business: seller identity, VAT, legal review (blocks selling).
2. No working email: no MX, no outbound email provider (Mailpit only), no SPF/DMARC.
3. No real payments (Stripe not configured; the Stripe test key shared in chat should be rolled).
4. No admin MFA (M4); no self-service account deletion/export.
5. Development passwords for the VM's internal databases (M5); `NODE_ENV=development` on the VM:
   the VM setup is a demo deployment. The production path is the Kubernetes/Terraform setup in
   `infrastructure/`, which requires real secrets (enforced in code for `NODE_ENV=production`).
6. Bot protection beyond rate limits (e.g. CAPTCHA on registration) not implemented; rate limits
   apply (10/min credentials, 5/min email-sending forms per IP).
7. Backups: the VM disk snapshot schedule is documented but not verified as enabled.
8. Accessibility and performance not measured in a browser (sections 9, 11).

## 19. Manual actions for the owner

1. **Apply the server fixes** (Cloud Shell; rebuilds all services, 30–45 minutes):

   ```bash
   gcloud compute ssh cse-api --zone=europe-west3-a \
     --command='cd /opt/cse/Market-place && sudo git pull && sudo deploy/gcp-vm/setup-vm.sh csekeyboards.com'
   ```

   It generates the new secrets, closes ordering, sends HSTS, and re-runs the catalog seed, which
   removes the demo ratings, badges and "was" prices.

2. **DNS** — until an email provider is set up, say the domain sends no mail:

   ```bash
   gcloud dns record-sets create csekeyboards.com. --zone=csekeyboards-com --type=TXT --ttl=3600 \
     --rrdatas='"v=spf1 -all"'
   gcloud dns record-sets create _dmarc.csekeyboards.com. --zone=csekeyboards-com --type=TXT \
     --ttl=3600 --rrdatas='"v=DMARC1; p=reject"'
   ```

   The apex already has a TXT record (`CODUL_TAU`): replace it, keeping your real Search
   Console code if Search Console says the property is verified by DNS
   (`gcloud dns record-sets update csekeyboards.com. --zone=csekeyboards-com --type=TXT
--ttl=300 --rrdatas='"v=spf1 -all"','"google-site-verification=<real code>"'`).

3. **Business and legal:** register the business; fill in every `[placeholder]` in
   `apps/web/src/lib/content.ts` (and `EMAIL_POSTAL_ADDRESS` on the VM); have a lawyer review the
   privacy policy, terms, returns, cookie policy and legal notice; then remove `draft: true`.
4. **Email:** choose a provider (e.g. Brevo, Resend, Amazon SES), set its SMTP settings for
   notification-service, add its SPF/DKIM records and relax DMARC accordingly; create a mailbox
   or forwarding for the contact address.
5. **Stripe:** roll the test secret key that was pasted in chat; for launch, use a restricted
   live key with `deploy/gcp-vm/enable-stripe.sh`.
6. **Accounts:** enable MFA (passkeys or authenticator app) on Google Cloud, Vercel, GitHub,
   the domain registrar and Stripe.
7. **Before opening:** confirm product and service claims, set Vercel
   `NEXT_PUBLIC_STORE_OPEN=true` and VM `ORDERS_ENABLED=true`.

## 20. Final production-readiness assessment

- **Security of the code base:** good. No open critical or high code-level vulnerabilities after
  the fixes; remaining items are medium (admin MFA) and operational.
- **Live deployment:** the storefront is patched and in preview now; the API server is safe to
  leave public **after** the VM update (step 1). Until then, orders can still be placed and
  "paid" through the simulator.
- **Legal / GDPR:** not compliant for selling, and this audit does not claim GDPR compliance. The
  pages describe the real processing truthfully, but the controller's identity, contact channel,
  processor agreements and legal review are missing.
- **Verdict:** ready as a non-selling preview (after step 1); **not ready to sell**.
